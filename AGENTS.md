# Evaluation rules

- Native speed reporting (2026-10-15): every task, each long-horizon stage, whole episode and diagnostic/probe reports Prefill and Decode in token/s alongside full wait, quality and token totals. For each round use summed native prompt_n/prompt_ms and predicted_n/predicted_ms, then median across rounds; never average per-call rates. Exclude reused cache_n from the Prefill numerator and report cache separately. Missing native timing is unknown, not zero or an estimate from wall time. Videos may use separate readable speed tables. Reporting supplements preserve frozen inputs and raw results.

- Model naming (2026-10-14): titles, covers, article introductions/configuration/conclusions, video introductions/configuration/conclusions and every comparison-table header identify the exact family version and model variant/size. Never label a standalone result only "Qwen", "千问" or "MiniMax". Keep version and variant in two-line video headers when space is limited. Record actual service/API IDs, quantization and engine separately. Contextual local/cloud pronouns are allowed after explicit identification.

- Every future capability comparison includes at least one frozen long-horizon episode from `long_horizon/`: persistent workspace/history, multiple dependent stages, requirement changes, an observed recoverable tool failure, final artifacts and regression checks. Long input, long output or repeated independent single questions do not qualify. Preserve stage snapshots, complete tool traces, time/token totals and failures; report end-to-end delivery before speed.

- Present every study in three stages: why evaluate, how evaluate (hardware, environment, prompts, settings, scoring), then results.
- Freeze prompts, reference answers and acceptance criteria before calls. Preserve failures, truncations and partial runs.
- Keep provider credentials, private addresses, SSH credentials and voice references out of Git.
- Never infer human approval, writing quality or equivalence from valid JSON or successful execution alone.
- Token Plan personal endpoints are for tool-integrated interactive use only. No unattended suite loops, load tests or scheduled batch calls through that channel. Each case is initiated and reviewed in the active agent conversation. Use a separately authorized channel for automation.
- A model alias does not prove that cloud and local weights are identical. Record the endpoint model ID, returned model, quantization, engine and dated environment snapshot.
- Article/video: explain why and how before the result section; in the result section pair each task with its actual outputs, differences and conclusion, then summarize. Do not turn these editorial instructions into spoken narration.
- Reader-facing articles and videos exclude owner operations such as restoring services, retaining defaults or rollback plans. Retain measured hardware/settings needed for reproduction. Give an explicit overall recommendation for the tested hardware and work, with quality/time/resources as reasons and the alternative's concrete use conditions.
- All client-directed explanations belong only in the conversation. Article prose, narration, subtitles, on-screen text, endings and public release copy address readers/viewers exclusively; exclude owner acceptance notes, pending confirmations, listening/publishing to-dos and other internal handoff text. Preserve factual scoring provenance and reproduction information without addressing the client.
- Paired results use aligned tables: one metric per row, fixed model columns, visible units and sample/median scope. Keep each task's differences and conclusion immediately after its results. Use narrow, styled tables in articles and phone-readable tables in video.
- Formal narration uses the owner's authorized voice. CosyVoice3 is permanently excluded. ASR and loudness checks do not replace listening review.
- Local-device comparisons run one inference model at a time. After boot inspect automatically started model services; before switching, stop the prior engine and wait for RAM/VRAM/GTT allocations to release. Check actual model processes and available memory before measured calls. Record host-specific admission thresholds in the study.
- After a runtime failure and reboot, diagnose retained kernel/service logs and driver readiness before resuming inference. Preserve original failed recordings; recovery does not replace them or establish an unverified root cause.
