# 100K+长上下文任务模板 v1

`corpus.py`生成可复现合成档案：分散政策、金额、状态与撤销证据，混入旧版本、草案、测试记录和不可信日志；LC01输出退款决策与证据，LC02输出结构化队列和交接备忘录。

首项冻结研究：[2026-10-20官方API比较](../studies/2026-10-20-deepseek-official-minimax-m31-flash)。研究目录保留独立源快照、实际完整提示词、冻结SHA、原始结果及说明。

## 后续使用

- 在模型调用前冻结任务、材料、schema、评分和预算；每个模型以API/引擎实际输入token大于100000才有长上下文资格。字符数、32K输入或另一个模型的token数不能替代。
- 每题两轮，报告质量、完整等待、输入/输出/缓存、原生Prefill与Decode。没有原生计时写未知，不倒算。
- 长上下文理解与`long_horizon/`的多阶段连续执行分开，两者后续都应包含。
- v1冻结grader对政策标识和证据字符串存在过窄词面匹配。首研究将原硬分与事后语义注释分开；后续新协议应在调用前明确政策字段表示、证据ID是否可含`DOC `、旧政策是否可出现在ignored中。修订须新版本、新冻结，不回写旧成绩。
- `runner.py`是研究快照风格的单案例入口，依赖对应研究的transport/config。逐项由活动会话启动、审读；不得据此在个人Token Plan接口上追加无人值守批量循环。

每个任务保留跨段关键证据、预期输出与失败；不能把快速截断当成高吞吐，也不能将字段词面偏差描述成金额计算错误。
