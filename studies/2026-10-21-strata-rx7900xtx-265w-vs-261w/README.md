# Qwen3.8 Next Flash：7900 XTX限265W，对比261W交付与速度

## 一、为什么做

7900 XTX在上一轮270W评测中出现过一次系统内存ECC可纠正错误，评测随即停止。这次将驱动功耗上限改为265W，完整重跑同一套工作任务，观察是否再次报警，并与261W的历史成绩对照。
重点有两个：265W能否完成这一轮负载；比261W多设4W，Prefill、Decode和完整交付是否获得可用的收益。一次无告警不能证明电源或内存的故障原因已经找到。

## 二、怎么做

同一Dell Precision5820、Xeon W-2133、128GB DDR4、7900 XTX24GB，沿用Qwen3.8 Next Flash的Unsloth UD-Q4_K_XL权重和Strata v0.1.44.1（HIP gfx1100）。引擎二进制及去密钥配置与原封存SHA一致；prefill auto、MTP spec4、65536上下文、int8 KV及其余参数不变。这轮比较功耗条件，不更新引擎或量化。

261W为2026-10-16历史成绩，265W为2026-10-21新跑27项：七短题各两轮、D01关闭思考诊断两轮、四阶段连续长程两轮、三类速度探针各三轮，另两次兼容检查不计分。题面、工具、预算与原硬评分版本沿用；本轮新功耗协议在请求前冻结。不同日期/启动，未做随机同期配对，小差值不能证明稳定提速。

265W在同一boot、此前270W新增一次ECC可纠正读错之后执行；起点CE=1、UE=0，计数未清零，对应页面已被内核软隔离。每次请求检查独占模型、功耗、boot、ECC及内存；约2秒硬件采样，任何新增ECC/驱动故障/预定温度或内存门槛失守即停。无新增错误不等于已修复DIMM或证明降功耗消除了故障。

代码使用独立功能断言，Agent分别验实际动作、权限和最终JSON；写作由AI助手按事实/完整/清楚/可用各0–5审读，至少16分并过硬项，未做盲审或真人验收。长程同一会话和工作区连续执行，含需求变更、回归、可恢复发布故障、最终产物和说明。

每题、每阶段、整项列原生Prefill和Decode。每轮按全部调用的新计算输入token/原生prefill秒、原生生成token/原生decode秒汇总，再取跨轮中位；复用缓存另列。完整等待包含API、工具等，隐藏验收时间排除。token含思考及重复历史；输出量变化时，等待不能直接代表硬件吞吐。32K只作吞吐探针，不是100K+理解能力测试。

硬件结论：265W正式任务窗口39.53分钟，包含加载的全部观察窗口41.38分钟。没有新增系统内存CE/UE、内核硬件或驱动故障，也没有重启；起点和结束均CE=1、UE=0，旧270W事件保留。驱动限额全程回读265W，但PPT平均功耗传感器有28个高于限额的采样，最高361W，其中4个超过280W；复查确认设备和限额正确，实际物理峰值未由外部仪表验证，不推断原因。261W历史采样也曾达270W，不能把任一cap当绝对瞬时功耗上限。边缘/热点最高63/84℃。两轮都无新增告警仍不能证明内存已修复、950W电源足够或不足。

## 综合结论

本轮对照更推荐261W。固定输入三轮中位的Prefill变化约−0.5%到+2.9%，Decode约−1.4%到+0.6%，4K和32K均未见值得提高功耗的吞吐收益。265W跑完且没有新增ECC，但短题没有多交付，长程也没有达到完整交付门槛。
用于金额纯函数、资源调度、库存预留等有明确验收的工作，两种功耗的核心功能相近；严格JSON应加格式校验，复杂决策文案需编辑，连续工程任务需检查每阶段是否按预算收尾。
这是同机、同量化、同引擎配置下对历史261W的有限样本对照。4W设定变化不能解释单次输出差异，也不足以推出全天稳定性、硬件故障根因或其他模型的结果。
