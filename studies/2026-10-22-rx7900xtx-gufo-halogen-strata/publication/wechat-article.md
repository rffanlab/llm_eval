# 7900 XTX跑Qwen3.8 Next Flash：Gufo、Halogen能替代Strata吗？

同样是AMD显卡，在本地AI Max+395上使用的Gufo和Halogen，能不能搬到24GB的7900 XTX上，替代Strata跑**Qwen3.8 Next Flash**？这次实际检查了Gufo v0.20.0和Halogen v0.18.13，又重新启动Strata v0.2.2验证推理。

**结果：前两套没有通过硬件检查，Strata完成了请求。**本轮无法给出三者同机的速度倍数。下面先把卡在哪里讲清楚，再列这台机器同日完整题库的实测，看看能承担哪些工作。

## 一、为什么做：395上的快，能搬到独立显卡上吗？

这台机器有128GB内存，但显卡只有24GB。要跑Qwen3.8 Next Flash的UD-Q4_K_XL权重，不能简单把128GB主内存与24GB显存当成一个高速池。引擎既要支持显卡架构，也要有相应的内存访问与计算路径。

Gufo、Halogen的公开成绩主要来自AI Max+395的统一内存系统。这次要确认的，就是它们能否在Xeon工作站加7900 XTX的组合上落地，再讨论速度收益。

## 二、怎么测：先过硬件门槛，再看完整交付

| 项目 | 本轮配置 |
| --- | --- |
| CPU / 内存 | Xeon W-2133，6核12线程 / 128GB DDR4 |
| 显卡 / 功耗上限 | RX 7900 XTX 24GB，gfx1100 / 265W |
| 主机PCIe链路 | 上游PCIe 3.0 ×16；显卡内部桥接端口另有4.0 ×16 |
| 系统 | Ubuntu 24.04.5，Linux 7.0.0-38 |
| 具体模型 / 量化 | Qwen3.8 Next Flash / Unsloth UD-Q4_K_XL |
| 版本 | Gufo v0.20.0 / Halogen v0.18.13 / Strata发行v0.2.2 |
| Strata内部版本 | engine / Control 0.1.47，不能与发行版号混用 |

Gufo使用已校验哈希的原版二进制，借用现有ROCm共享库运行GPU诊断，没有加载模型。Halogen使用固定tag入口脚本的原始硬件预检函数，在真实系统上单独执行，没有启动完整容器。没有修改内核、提高功耗或伪装GPU型号。

265W是驱动回读的功耗上限配置，不能当成每一瞬间的实测值或插座功耗；同日原始监控中的瞬时读数曾超过这个配置值。

通过兼容性检查的Strata使用同一份既有权重、原生GGUF与pack、MTP spec=4、spec-min-p=0.5、Prefill auto、expert-cache auto、int8 KV、32K KV常驻和1500MiB显存预留。短题及长程配置64K上下文；100K材料另用128K配置。思考为medium，temperature=0；固定512输出的吞吐探针关闭思考。

本轮新增一次独立推理验证。完整工作表现引用同日已完成、已冻结的两轮短题与连续项目，以及三轮吞吐探针、两轮100K测试；原始文件逐一校验哈希，**不把引用成绩写成这次重新跑过，也不把新调用混进旧轮次**。

表内等待是请求或完整阶段的墙钟耗时；Prefill只计算本次新处理的输入，缓存另列；Decode按原生生成数计算，包含思考。多调用先在每轮汇总token与原生时间，再取跨轮中位。字数、格式、功能断言和编辑评分分别验收，写作编辑门槛16/20；编辑分为沿用的AI审读分，不是人工验收。

## 三、测试结果

## 1. Gufo：二进制能启动，GPU检查不通过

| 检查项 | Qwen3.8 Next Flash Gufo v0.20.0 |
| --- | --- |
| 版本命令 | 正常返回v0.20.0与固定commit |
| 实机检测 | AMD Radeon RX 7900 XTX / gfx1100 |
| 官方要求 | gfx1151，Radeon 8060S / 8050S |
| 诊断结果 | FAIL，退出码1 |
| 模型加载 / Prefill / Decode | 未运行 / 不适用 / 不适用 |

这次不是缺库导致二进制打不开：版本命令成功，诊断也正确识别了7900 XTX。失败的是官方GPU架构门槛。上游CMake同样硬性要求gfx1151，直接把编译目标改成gfx1100也会被拒绝。**当前原版Gufo不能作为这台7900 XTX的替代方案。**

## 2. Halogen：官方硬件预检同样拒绝

| 检查项 | Qwen3.8 Next Flash Halogen v0.18.13 |
| --- | --- |
| 执行方式 | 原样独立执行host_preflight()，非完整容器启动 |
| 内核报告目标 | 110000，对应gfx1100 |
| 引擎要求目标 | 110501，对应gfx1151 |
| 预检结果 | 不支持，退出码1 |
| 模型加载 / Prefill / Decode | 未运行 / 不适用 / 不适用 |

Halogen的当前说明直接限定一个GPU架构，并无通用回退路径；入口脚本也在实际机器上给出了相同判断。**这个版本同样不能在这台机器上进入正式工作评测。**这说明当前支持范围，不能据此断言以后永远无法移植。

## 综合推荐：这台7900 XTX，选Strata v0.2.2

**在Xeon W-2133、128GB DDR4、RX7900 XTX 24GB、265W这套配置上，三套候选中推荐Strata v0.2.2跑Qwen3.8 Next Flash UD-Q4_K_XL。**它通过了当前推理验证，同日短题严格交付11/14，金额函数、资源调度、简单抽取和受控库存操作两轮均通过，固定512输出的Decode约48—49 token/s。

Gufo v0.20.0和Halogen v0.18.13当前都限定gfx1151，适用AI Max+395这一类设备，不能把那里的速度成绩搬到7900 XTX上。它们在本机没有推理速度可比，不列快慢名次。

Strata更适合有明确输入、测试和工具权限的代码与操作任务。复杂备忘录两轮未过编辑门槛，长程第一阶段未收尾，100K引用ID也未满足协议：这些工作可以借它起草或计算，最终还需要检查事实、阶段结束和机器接口。
