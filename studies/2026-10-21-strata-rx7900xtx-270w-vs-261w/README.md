# Qwen3.8 Next Flash：7900 XTX 270W对比261W（中途因ECC停止）

## 为什么做

把同一张7900 XTX的功耗控制值由261W提高到270W，观察Strata跑同一模型是否更快、交付是否变化，以及是否重现宕机。

**本轮没有跑完：监测约5.1分钟后新增一次系统内存ECC可纠正错误，按事前门槛停止模型。没有重启或GPU复位记录，不能把这次告警归因为显卡或电源，也不能据此宣布270W稳定。**

## 怎么做

调用日期：270W为2026-10-21新测；261W为2026-10-16封存历史。Dell5820、Xeon W-2133、128GB、RX7900 XTX24GB；Qwen3.8 Next Flash、Unsloth UD-Q4_K_XL、Strata v0.1.44.1（gfx1100）。部署配置SHA与历史封存一致，未升级引擎或更换量化。

prefill auto、MTP spec4、最大上下文65536、int8 KV及其余参数均沿用。原计划27项：七短题各两轮、D01关闭思考诊断两轮、四阶段长程两轮、三类速度探针各三轮。题面、工具、预算、原分先冻结。代码用独立功能断言，工具核对动作/权限/JSON，写作由AI助手按事实/完整/清楚/可用各0—5审读，至少16分并过硬项，未盲审。

每次调用前准入；硬件约2秒采样、约10秒检查内核。新增ECC、驱动故障、boot变化、功耗设置变化、温度/内存门槛失守即停止。原生Prefill按新计算输入token/计算秒；Decode按原生生成token/计算秒。每轮先汇总，再跨两轮取中位；缓存另列，完整等待独立。32K只是匹配历史的吞吐探针，不是100K+理解成绩；这轮连这些探针也尚未执行。

完整提示词、预算与标准：[task-cards.md](task-cards.md)、[tasks.json](tasks.json)、[四阶段](long-horizon/task.json)、[本轮预登记](power-comparison-protocol.md)。

驱动功耗上限不是整机插座功耗或瞬时峰值保证；两个观察窗口长度不同，含工具和任务间隔。270W的153条约2秒采样最高264W、边缘59℃、热点79℃，不能用这5分钟证明全天稳定性。

固件与EDAC共同指向系统内存DIMM3（16GB DDR4，2133MT/s，MC0/channel1/slot0）。内核记录一次可纠正读错，并软隔离对应物理页；同一地址还有MCE/APEI重复上报，不等于三条不同内存坏了。未纠正错误计数0，机器boot ID未变；模型已停止。告警证明本轮存在内存子系统异常，不能仅凭一次事件判断永久坏条、270W致错或950W电源不足。

## 本轮结论

**没有证据推荐从261W升级到270W。** 前四类题均8/8交付，Decode中位变化约−1.9%到+1.7%，没有一致且明显的提升；复杂题、长程及吞吐探针没有完整结果。261W是已有完整27项且该观察窗口无新增ECC的历史基线；270W本轮未通过“无新增硬件错误”的门槛。这个结论只针对现有证据，不表示261W已证明能消除DIMM告警。

本次中断与原始结果保留。硬件事件附近的样本不计入功耗收益，未执行项不补零；完整项目能力和吞吐提升仍没有本轮证据。
